# TestCase Agent 评估维度地图（三层体系）

> 规划日期：2026-08-12　状态更新：2026-08-13

> 配套工具链见 `backend/tests/eval/README.md`。

## 第一层：产出卫生检查（代码规则，零 token 零校准）

这些维度不需要 LLM，写脚本扫就行——727 条存量用例统计已暴露问题：

| 维度 | 评什么 | 已有证据 |
|------|--------|---------|
| 字段规范一致性 | priority 是否单体系（critical/high 与 P0/P1 不得混用）、case_type 是否必填 | 实测：priority 双轨并存、77 条缺 case_type——存量数据已经在违规 |
| 追溯编号覆盖率 | remarks 是否含 REQ-/FP- 编号（用例必须有需求出处） | 抽样看大部分有，覆盖率可量化 |
| 步骤数合理性 | 单条用例步骤 >10 步（该拆）或只有 1 步（多半没操作就断言） | 代码分布统计 |
| 用例命名规范 | 动宾结构一致性（"编辑地点-修改类型后保存"），禁"测试1""test" | 代码可查 |

四维度合并为 `lint_cases.py`（用例 lint），不走校准流程，直接当确定性门禁用——
它是 G-Eval 的互补：**代码查规范，裁判查语义**。

## 第二层：产出语义质量（LLM 裁判，每个都要走校准）

| 维度 | 评什么 | 为什么值得 |
|------|--------|-----------|
| 原子性（A 类） | 一条用例是否塞了多个不相关检查点 | 对抗评审维度 8；直接可评 |
| 因果对应（A 类） | 每个 step 的 result 是否真是该操作的结果 | 比"没操作却断言"更细的断裂 |
| 前置条件自洽（A 类） | test_data 里的账号/数据在 preconditions 里是否有交代 | 对抗评审维度 1 的可离线部分 |
| 覆盖完整性（B 类） | 功能矩阵每个 test_point 是否至少被一条用例覆盖、P0 密度 | 漏测风险最致命的维度 |
| 测试数据可构造性 | test_data 是具体值（testuser@test.local）还是抽象描述（"合法用户名"）——后者新人根本没法执行 | 对抗评审维度 6 的核心；存量里 login 样本数据很具体，但不少样本是"原类型→检测实验室"这种半抽象 |
| 负向断言 | 只断言"成功时怎样"，没断言"不该发生什么"（如越权操作后其他用户数据不可见、失败操作不产生脏数据） | 烂用例的典型死因：验证了 happy path，漏了副作用检查 |
| 需求忠实度（幻觉用例） | 用例验证的功能点在需求里根本不存在——AI 自由发挥编出来的 | 比覆盖不完整更危险：覆盖不全只是漏，幻觉用例是错 |

## 第三层：过程质量（评 Agent 怎么干活的，新数据源）

不只评产出，还评生成过程本身。数据从 Langfuse trace 采（已接入观测）：

| 维度 | 评什么 | 数据来源 |
|------|--------|---------|
| 质量防线有效性 | 红线中间件拦截了多少次违规创建、自检中间件触发了几次——拦截率本身就是 Agent 质量信号 | 中间件日志/trace |
| 对抗评审发现率 | 每次生成评审子代理发现多少缺陷——发现率持续为 0 是评审失效的信号，持续很高说明主 Agent prompt 有问题 | 评审结果文件 |
| 重复运行稳定性 | 同一需求跑两次，产出一致吗？（业界 2026 年 agent 评估的标准项） | 主动跑批 |
| 生成效率 | 单模块生成的轮次/token/工具调用数——prompt 改版的隐性成本 | Langfuse 用量统计 |

特殊价值：平台中间件是独创的重度设计（11 个中间件），"中间件防线到底
拦住了多少问题"是博客和面试里最硬的量化证据，目前没有在统计它。

## 取舍建议：别贪多

每个 LLM 裁判都要走一遍盲标校准，维度膨胀 = 人力膨胀。按死因优先级排：

1. ~~立刻做：第一层 lint~~ —— ✅ 已完成（lint + 运行时 warning 通道）
2. ~~校准通过后做：B 类双文件采集~~ —— ✅ 已完成（regression_v2 带矩阵）
3. **下一步候选**：
   - a) 覆盖完整性裁判（半代码化：FP 编号直接匹配 + LLM 兜底）
   - b) 需求忠实度裁判（查幻觉用例，与 a 共用 v2 数据）
   - c) 负向断言、测试数据可构造性（A 类，v1 数据直接可评）
   - d) 第三层防线有效性统计（博客素材向）
4. 若重启 LLM 裁判：盲标校准工具链（make_blind_labels / collect_labels /
   run_judges / calibrate_report）全套现成，45 条 v1 样本待标。

第三层回答"你的防线有没有用"。**
